# Murim 실제 독자·시청자 기반 시장 검증 계약 v1.0

## 1. 최종 목표
상업 콘텐츠의 가치는 실제 목표 독자·시청자의 자발적 선택, 재미와 발견, 지속적 소비 및 재방문으로 검증한다. LLM/전문가의 평가가 높아도 독자 반응을 대신하지 못한다. 독자 선호는 시장 검증의 핵심이며 사료 진실성, 권리, 안전, 전문 기술 검증은 별도 필수 조건이다. 인기만으로 작품의 모든 예술적 가치가 결정되는 것은 아니다. 사용자가 정한 장르/목표 관객/작품 의도를 보호한다.

## 2. 저비용 사전 실증과 단계별 확대
독자 창작 또는 권리 확보 brief → 전문 생성 방법별 실제 원고 → 내부 결함 검사 → 허용된 독자 평가단의 블라인드 비교 → 허용된 연재 플랫폼에서 승인된 파일럿 → 연독/독자 반응 분석 → 후속 원고 및 스킬 개선 후보 → 독립 신규 표본 재평가 → 시장 반응 확인된 IP의 영상 각색/저비용 animatic → 실제 시청자 검증 → 권한 내 제작 확대.
웹소설/영상은 서로 다른 매체다. 소설용 원고와 영상용 screenplay/shot plan을 분리하고 공통 Story State/인물/사건/권리/의도 revision으로 결속. 소설 성공은 서사 수요의 증거이지 영화적 완성도나 영상 시장 성공의 증명 아님. 모든 작품에 장기 연재를 강제하지 않는다. 단편/역사 다큐/시각 중심 작품은 해당 매체의 직접 관객 평가를 병행 또는 선택한다. 외부 게시 이전 인간 승인과 권리/플랫폼 조건 확인 필수. 기존 G1–G4 제작 승인 및 D0–D5 설계 심사 유지.

## 4. 실제 독자 평가 설계
- 유입: 노출 수, 제목/소개/표지 클릭률(제공되는 경우), 1화 진입. 유입 실패와 이야기 실패 구분. 노출 자체가 부족하면 INSUFFICIENT_EXPOSURE; 인기 없음으로 단정 금지.
- 지속 독서: 회차별 독자/조회수(정의 구분), 동일 cohort의 다음 회차 진입/완독률(실제 제공되는 경우), 선호작/재방문/구독/다음 회차 기대, 이탈 시점. 누적 조회수만 있으면 같은 관측 기간의 회차별 조회 비율을 proxy로 기록하고 실제 개인 연독률로 표시하지 않는다.
- 질적 반응: 구체적 댓글, 재미/긴장/인물 공감/다음 회차 기대/지루함/개연성/이해 혼란 등. 긍정·부정·무응답 모두 보존. 침묵 독자와 댓글 작성자의 선택 편향, 스팸, 극단 평가 구분. 댓글만으로 인과 단정하지 않음.
- 시장: 자발적 추천/재방문, 허용된 실제 유료 전환 및 경제성. 무료 독자 선호와 구매 의사는 별도.
- 영상: 실제 완성 영상에 대한 시청 지속/완주/재시청/댓글/추천 및 사용자·관객 관측. 소설 지표와 직접 동일 척도로 합산 금지.
같은 장르·길이·연재 주기·공개 기간·노출/유입 경로·무료/유료·계정 규모를 가능한 한 맞추고 교란 기록. 독자 평가단에서는 brief/길이/순서를 통제하고 작품 정체를 가리되 AI 이용 사실 표시 의무/참여 동의는 유지. 모집과 대조군, 주요 지표, 최소 표본/기간 및 의미 있는 효과 기준을 결과 이전에 확정. 소표본/관측 부족은 HOLD/INCONCLUSIVE. 인기작 상위권만 선택한 비교는 생존 편향을 표시. 기준 수치는 실제 파일럿 분포로 결정; 임의 연독률 80% 등 합격선 금지.

## 5. 독자 피드백 캐스케이드
독자 지표/댓글/작품 revision 결속 → 전문 분석 Add-on이 반복되는 실제 불만/장점과 인과 가설을 분리 → 원고 위치/장면/부모-자식 작업 및 원인 후보 연결 → 개선 전략 비교 → 아직 공개되지 않은 후속 회차 또는 별도 승인된 개정본에 수정 → 독립 독자 표본/회차로 검증 → 작품 효과 및 한계 기록.
이미 게시된 작품의 원문/이력과 독자 기대 보존. 게시본 몰래 수정, 댓글에 따른 무조건적 전개 변경, 불법/허위/자극적 클릭 유도 금지. 장기 작품의 세계관·복선·결말 등 고유성 보호. 단일 댓글이 전역 스킬 변경을 결정하지 않는다. 여러 독립 작품/표본에서 효과가 재현된 가설만 스킬 challenger로 격리 → 별도 holdout 평가 → Manager 승인/채택 또는 유지. 개인정보/댓글 원문 학습 권한 미확보 시 익명화된 허용 집계·가설만 활용.

## 6. 5축 및 평가 역할
Core: generic version/evidence/metric/observation 계약. Bridge: 채널/평가 Add-on 연결 및 실행. Add-on: 허용 채널 수집/전문 독자 반응 분석·매체 각색·개선 제안. Persistence: 작품/관측 기간/집계 정의/출처·권한/버전/해시/실험·평가·승인 이력. Manager: 정책/실험/비교/증거 인증/자원·권리/승격/rollback 및 관측. 플랫폼별 전용 하드코딩은 Core/Manager/Bridge/shell에 금지. 기본 화면에는 재미·독자 반응·개선된 작품을 쉽게 설명하고 복잡한 통계/오류는 기계검증에 모은다.
전문가/LLM은 사전 결함 탐지와 개선 가설 생성·평가 보정; 실제 독자는 시장 선택; 시청자는 영상 경험; 실제 고객은 앱의 사용성/경제성 검증. 작품 시장성은 앱 시장성의 충분조건 아님.
