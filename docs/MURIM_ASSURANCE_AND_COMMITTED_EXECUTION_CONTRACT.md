## 1. 선행 입증 후 집중 실행
시장·장르·주제·사업모델·시나리오·기술 선택·전체 설계 등 고비용/비가역 결정을 내리기 전에 가장 위험한 가정부터 반증한다. 검증되지 않은 방향에 본격 개발비/제작비/홍보비를 투입하지 않는다. 기존 자료와 도구로 가능한 비용 낮은 반증·비교를 먼저 수행; 실제 결과가 필요한 가정은 사전 승인된 작은 실물 실험으로 검증한다. 본편 제작 후 비로소 수요/핵심 기술 실현성을 조사하는 방식 금지. 연구 실험과 사업 투자, 설계 검증과 제품 인수, 작품 완성 및 시장 성과를 별도로 판정.
엄격함은 질문 개수나 높은 자기평가 점수가 아니라 중요한 주장에 반증 가능한 기준과 직접 근거가 모두 있다는 의미다. 미래 시장·인간 취향·기술은 불확실하므로 어떤 심사도 흥행/무손실을 보장하지 않는다. 합격은 명시된 적용 조건에서 허용할 수 있는 잔여 위험과 입증된 우위를 근거로 다음 제한된 실행을 승인하는 것. 모든 상상 가능한 질문에 무한 답변할 필요는 없다. 중대한 가정/위험/요구에 대응하는 심사 항목 전수와 사전에 고정한 종료조건으로 심사 범위를 닫는다.

## 2. 모든 전문 공정의 필수 주장-근거 계약
각 capability/프로젝트/비교 범위에 대해 아래를 갖춘 versioned review dossier가 필요하다. 문서 작성 자체로 합격 불가.
- 목적과 고객/부모 요구, 출력 실물, 적용 장르·매체·관객/시장·환경/시간·예산. 왜 필요한가, 무엇이 실패인가, 성공 결과가 다음 단계에 어떤 가치인가.
- 경쟁 기준: 현행 champion, 강한 실사용 경쟁 도구/전문가 및 비교 가능한 대안. 가장 높은 품질/속도/경제성을 동일 조건에서 관측할 수 있도록 비교 단위·자원·입력 고정. 광고/수상/공개 시연은 원출처 주장이지 직접 품질 증거가 아님.
- 핵심 가정과 실패 모드: 발생 원인, 영향/심각도, 관측 가능성, 대안, 예방·탐지·복구·검증. 재현 가능한 반례 및 예상 밖 입력. 과거 실패는 우선 반증 대상으로 등록.
- 필수 requirement_id별 criterion_id, 부모 요구 참조, 실물 revision/hash, 측정 단위/방향, 측정 도구와 절차, 비교군/데이터 권리·시점/모집단·표본 및 seed/반복, 하한/상한/최소 효과·초과 목표, 허용 불확실성, 심사자와 독립성, 실패 보완 및 invalidation 범위, 예산/기간/시도 상한, 유효기간/재심사 trigger. 요구와 테스트를 양방향 추적. N/A는 applicability 근거 및 독립 확인 필요, 무평가를 N/A로 숨기지 않음.
- 실제 관측 원장: method/version, input/output/evidence hash, 원천과 관측 범위, 독립 reviewer provenance, 실제 값/결함/누락/불확실성, 비교·반례·재실행 결과, 부정 증거 및 중복·상관. 시험 결과와 판단, 가설/추정과 실측을 분리.
- 합격 시 다음 단계 허용 범위/지출/권한/잠금 입력·승인, 잔여 위험·유효조건과 정량 감시/중단 조건. 미래 자료/가정 변경 때 영향을 받을 downstream 기록.
공통 질문은 '무엇이 증명되어야 하는가?', '어떤 실제 자료가 이 주장을 반증하는가?', '어떤 기준을 넘으면 합격인가?', '누가 얼마나 정확히 평가할 수 있는가?', '기존보다 나은가?', '실패 시 어디를 어떻게 바꾸는가?', '이 결정이 바뀌려면 어떤 새로운 증거가 필요한가?'. 포괄 질문은 Add-on별 구체 요구/실험으로 분해. 응답 길이/형식/자기 확신은 증거 아님.

## 3. 공통 합격 판정
판정 유형을 구분한다.
A 객관 필수: 권리/사실/필수 인터페이스/필수 산출물/승인/정합/안전 등. 적용되는 모든 hard check PASS, 미평가 필수 항목 0, 미해결 blocker 0, 누락 요구 0, stale/mismatched/unauthenticated 필수 evidence 0. 다수결/평균으로 상쇄 금지. 표본 시험의 관측 결함 0은 실제 전체 결함률 0을 의미하지 않음.
B 전문/관객 의미 평가: 장르/매체별 실제 비교 기준과 의미 있는 효과 크기, 독립 평가·사람 보정·불확실성 및 하위 품질/실패율. 예: 높을수록 좋은 지표는 신뢰 하한이 목표 이상, 낮을수록 좋은 지표는 상한이 허용 한계 이하, 비교 우위는 차이의 보수적 경계가 사전 고정 margin 초과. 필수 비열화 지표는 사전 허용 한계 충족. 정성 판정도 anchor/예시·반례·전문 독립 심사 및 불일치 해결 조건을 고정. 미해결 중요한 반대 증거=FAIL/INCONCLUSIVE. 동일 LLM 반복/동계열 합의는 독립 사람 판단 대체 아님. 기존 G1/G2 95/100·개별 9/10 등 하한은 유지하되 보정 없는 점수는 합격 근거 아님.
C 사업/생산/운영: 실제 품질을 충족한 산출물당 비용/시간, 실제 시장 수익 경로/완전 원가/보수적 하방, 적합한 제품 실사용 및 운영 위험. 시장은 MARKET-M0~M6의 독립 조건을 적용. 해당 조건 모두 충족 전 전체 합격 금지. 품질·시간·비용의 trade-off는 사전 요구와 비교 제약으로 결정.
공통 논리: READY = 평가계약의 실제 보정/검증 + 모든 적용 필수 증거 유효 + 모든 hard check 통과 + 필수 target/비교 margin 충족 + 중요 반증 해결 + 모든 필수 child의 유효 승격 + 부모 통합 독립 평가 + 권한/승인. 논리적 AND이며 평균점수 아님. 데이터 부족/미연결/판정 불확실성은 FAIL(현 제출의 수용 불가) 또는 INCONCLUSIVE/NOT_EVALUATED로 원인 기록, 승격 금지.
수치 정책은 실제 baseline 분포·사용 목적·경제성/실패 위험·전문 표준으로 보정하고 독립 평가 이전 잠금. 현 상태 미보정 항목에 임의 90점/95점/승률/고정 표본수로 합격시키지 않는다. 사전에 승인된 연구 상한 내 가장 적은 비용으로 중요한 반증부터 수행. 후보 기준/원칙 변경은 별도 새 버전과 비교 검증; 기존 실패작을 통과시키는 기준 하향 금지.

## 4. 심사 자체의 검증
NASA Software Engineering Handbook: https://swehb.nasa.gov/pages/viewpage.action?pageId=163119240 및 https://www.nasa.gov/reference/system-engineering-handbook-appendix/ 의 진입/통과 조건 및 요구-검증 추적성. NIST AI RMF Measure https://airc.nist.gov/airmf-resources/airmf/5-sec-core/ 및 https://airc.nist.gov/airmf-resources/playbook/measure/ 의 독립 평가, 불확실성, 반복 가능한 TEVV 및 측정 타당성. https://www.nist.gov/artificial-intelligence/ai-research/tevv-athlon-framework-evaluating-ai-systems 참조 후보. 해당 프레임워크를 콘텐츠 산업 인증/흥행 보증으로 오인하지 않고 실제 적용 효과 비교.
평가 기준의 검증은 전문 결과의 검증보다 먼저 수행한다. 알려진 좋은/나쁜/경계 사례, 중요한 결함을 심은 반례(합성은 평가기 시험용으로만), 가짜 증거/누락·stale·시간누출·동일모델 편향·표면 유사성·실패/권리·통합 오류를 시험. 알려진 중요 결함의 관측 false accept 0, 분류 혼동과 불확실성, 사람 간 불일치 및 평가자-사람 일치/재현, 독립 holdout, 미지의 실제 입력에서 오탐·미탐의 허용 상한을 사전 고정/검증. 단순 0건 관측으로 미탐률 0 주장 금지. 평가 반복/다중비교 및 후보 최적화에 따른 과적합 통제. 모델/프롬프트 변경 시 재보정. 강한 기존 평가/선정 방식보다 실제 좋은 결과 선택, 실패/비용 감소가 입증되지 않으면 해당 평가 방법을 개선 또는 교체.
개발 LLM의 조사와 자체 문서 검토는 독립 평가 완료 아님. 실제 독립 전문가/관객/모델·실물 접근의 미확보는 원인과 해결 경로/대안을 기록. 합성 fixture, 샘플 응답, 외부 발표, 이 문서 검토로 D3/D4 통과 금지.

## 5. 진행 상태 및 재작업
상태 예시(기존 계약에 매핑, 새 폐쇄 enum 아님): RESEARCH → CONTRACT_READY → EVALUATION_QUALIFIED → EXECUTION_ELIGIBLE(권한 내 시험/생산 단계 명시) → ACCEPTED_BASELINE → FORWARD_EXECUTION; 실패는 REWORK/INCONCLUSIVE/BLOCKED/REJECTED, 기존 결과의 위험은 STALE/QUARANTINED. 전체 설계 D0~D5 OK 전 신규 제품 코드 실행 불가, 기존 도구의 사전 실험은 명시적 허용 범위만.
원인 분류 TEST_DEFECT / PRODUCT_DEFECT / AUTHORITY_DRIFT / ENVIRONMENT_ISSUE / UNKNOWN. 전문 실패는 시장/개념/기술/경제/증거 등 세부 원인 기록. 필요한 증거, 현재 확보 경로/대체 경로, 가역 수정 가설, 책임 capability, 재검증 조건, 승인 범위 내 예산/기간/시도, 종료 기준을 명시한다. 승인 범위 내 대안을 적극 검토하되 같은 시도 무한 반복 금지. 상한 소진/필수 근거 접근 불가/대체 전략 없음은 해당 후보 제외 또는 HOLD, 원인과 재개 조건 기록. 승인·권리·비용 제한 우회 금지. '미검증'을 최종 보고의 유일한 내용으로 사용 금지.

## 6. 합격된 방향 잠금과 신뢰도 증가
승격 시 입력/출력/요구/평가 기준·비교군/증거·스킬/엔진/정책/권한·승인 revision과 digest, 적용범위, 잔여위험/감시조건을 immutable Accepted Baseline으로 기록. 실제 제품 구현 전에는 문서/증거 계약만. 같은 입력/조건에서 해당 합격을 재사용하고 새로운 LLM 의견, 유행, 더 최신 버전만으로 전면 재평가 금지. 모순되는 새로운 객관 근거/상위 요구 변경/의존 버전 변경/권리·시장·비용·장비 등 적용 조건의 유의미한 이탈/독립 검증 실패/유효기한 경과가 발생할 때만 변경심사. 만료는 곧 품질 실패가 아님, 필요한 증거 갱신. 중대 위험 발생은 즉시 해당 실행 중지/격리 가능.
변경 제안은 기존 대비 실제 문제/새 근거, 영향 DAG, 예상 개선/비용, 유지할 우수 부분 및 비교 실험/rollback을 포함. 기존 champion과 후보를 같은 조건에서 비교하고 필수 비열화 및 최소 효과·경제성 기준 통과 전 교체 금지. 불리한 결과는 후보 폐기/격리, 기존 검증된 방향 유지(안전/권리/실증된 결함 제외). 이미 승인된 작품/원본 덮어쓰기 금지. 영향받은 자식/조상/후속만 stale, 무관 sibling은 재작업하지 않음. 시장 변동과 최신 기술 감시는 별도 연구 루프, 실제 진행 중 작품의 무분별한 방향 전환 금지.
신뢰도는 증거 coverage/직접성/독립 재현/관측 오차 및 잔여위험의 개선으로 설명한다. 서로 상관된 점수나 단계별 합격률을 곱하거나 합산해 임의 성공 확률 산출 금지. 통합 작품/시장 전체 결과는 별도 검증. 전체 합격 후에도 채널/국가/분량 확대는 검증된 적용 범위와 승인된 사업 한도 안에서만. 다른 시장/새 기술/큰 투자 등 범위 변경은 해당 차이만 다시 심사한다. 실행 중 사전 정의한 중단·확대 기준과 실제 현금흐름/품질 감시로 불필요한 전환과 손실 확대를 동시에 방지.

## 7. 5축 및 승인 경계
Core generic contract/reference/state primitives. Bridge feature-blind 실행 및 관측 전달. Add-on 전문 질문/생산/검사/분석/대안, 자기 최종 승인 금지. JSON persistence-only, immutable evidence/baseline/change history. Central Manager 공통 orchestration/권한/증거·게이트/승격·의존 무효화·비용·변경심사; 전문 판단 하드코딩 금지. UI는 중요한 결정/실물·신뢰 근거와 실제 blocker만 자연어로 제시, 기계검증 탭에 상세 심사/증거/변경 그래프. 승인된 연구의 기술 판단을 사용자에게 넘기지 않는다. 실제 지출/게시/외부 전송/권리 및 기존 G1~G4 인간 승인과 D0~D5 유지.

## 8. 현재 상태
공정별 최소 심사 구조/반증 질문·시험·보완/잠금 규칙을 문서화. 공정별 수치와 전문 평가기의 실제 보정, 실물 독립 비교, 시장 수익 모델 실증 미완료. [공정별 원장](research/assurance/STAGE_ACCEPTANCE_REGISTER.md)의 예비 규칙에 따라 다음 연구는 실제 자료 접근과 평가 방법 자체의 검증, 대표 고위험 가정의 사전 실증. 이번 문서 작성은 실행 엔진 구현, 전체 설계 OK 또는 시장 경쟁력 입증이 아니다. DESIGN_HOLD / PRODUCT_CODING_FROZEN 유지.
