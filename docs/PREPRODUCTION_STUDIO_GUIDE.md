# Murim Studio — 제작 전 품질 게이트 사용법

## 목적
기존 4-GATE의 기획/편집 품질 G1·G2를 실제 제작 전에 강제한다. 기존 제작 도구는 폐기하지 않고 사전 승인 뒤 실행한다. 실제 영상 품질 10축은 [VIEWER_VALUE_GATE_V1](VIEWER_VALUE_GATE_V1.md) 그대로 유지한다.

## 기존 세한도 작품에서 시작
Windows Web UI를 종료하고 main을 fast-forward 동기화한 뒤 run-studio.cmd로 다시 시작. http://127.0.0.1:8080/studio/ 에서 기존 저장 작품 선택 후 작품 열기. 이미 불러온 프로젝트는 다시 import하지 않는다.

- **00C**: 기존 실패작 A와 원본 기획·장면 정보를 확인. 저장소의 38.5점/4개 문제는 알려진 기록 요약일 뿐 Gemini 원문이 아니다. 기존 Gemini 답변 전체를 붙여 넣고 원문에서 지적한 *모든* 문제를 한 줄씩 기록하여 등록.
- **00A**: 작품 목적, 시청자, 제작 방침, 전체 이야기, 사료·출처, 미술·영상, 음향, 결말을 정리. 외부 LLM 수정 요청서를 복사해 별도의 수정 담당 LLM에 전달. JSON 응답을 가져와 인간이 직접 검토하고 보완. 가져오기만으로 저장/승인이 일어나지 않는다.
- **00B**: 실제 장면 제목·길이·발화·자막, 화면·동작·음향 및 사료 설계를 검수. 장면 추가/제거/순서 변경 가능. 변경 이유를 기록하고 새 수정본 저장. 미완성 초안 저장은 허용되지만 심사/제작은 잠긴다.
- **00C**: 이전 버전 및 해당 심사 원문을 비교. 현재 저장된 버전의 심사 요청서를 복사하여 별도 독립 심사 세션에 전달, 응답 JSON 원문 및 리뷰어 정보를 등록. 6개 편집 평가축(시청 가치를 제공하는가/서사/역사·근거/시각 설계/음향 설계/전체 정합성) 동일 가중 환산 95점 이상, 각 9점 이상, 모든 이전 결함의 구체적 해결 증거, 신규 문제 0개, verdict PASS를 검증. 하나라도 미달/미평가이면 HOLD 또는 REWORK_REQUIRED. 같은 수정본 재점수 입력은 불가. 기존·새 문제를 함께 고쳐 새 버전을 저장해야 한다.
- 위 조건을 만족하면 사용자 직접 원문/사료/실제 수정 여부를 검토하고 인간 승인을 입력. 승인 후 실제 장면과 대본이 M-VML에 전달되고 제작 탭이 열린다. 이전 실패 작품 및 원본 데이터는 그대로 남으며 미디어는 자동 배치되지 않는다. 미술·음향 등 실제 자산은 승인 계획 기준으로 검수·선택한다.
- 제작 탭의 승인된 장면 방침을 참조. 시나리오의 장면 목록·제목·길이·실제 발화는 잠겨 있으며 변경은 00B 새 버전과 재심사로 돌아간다. 미세 트랙 수정은 허용. 06에서 실제 영상 평가 기록을 연결할 수 있다. 구조 결함이면 원문과 결함 목록을 입력하여 **사전 제작 재심사로 반환**: 실제 영상 SHA가 함께 저장되고 제작이 잠긴다.

## 프로젝트 이력
기존 M-VML 리비전은 보존. 제작 계획은 프로젝트별 outputs/studio/<project-id>/preproduction의 해시 연결 원본/수정본/평가/승인 이벤트로 관리한다. 발화·구성은 실제 사용될 M-VML에 승인 계획 해시와 함께 전달되며 출력 receipt에도 해시가 기록된다. 이전 실제 렌더는 이미 등록된 비교 대상으로 보존된다.

## 범위
외부 LLM은 인간 매개로 실제 답변을 옮기는 방식이며 외부 API 직접 호출이나 응답의 독립성/진실성을 자동 인증하지 않는다. 의미적 결함의 실제 해결은 독립 평가 및 인간 승인과 사료 검토가 필요하다. 점수만 높거나 수정안만 가져왔다고 합격하지 않는다. 최종 실제 영상의 음질·영상미·사실·시청 가치 등은 별도 심사한다. Windows 실제 Web UI/GPU 실행 미확인 상태는 CURRENT_STATE 참조.
