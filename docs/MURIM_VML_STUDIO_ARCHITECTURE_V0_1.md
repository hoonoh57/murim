# Murim VML (Video Markup Language) & Studio — architecture proposal v0.1

2026-11-22 KST. Status: **DESIGN_PROPOSED / LANGUAGE_NOT_IMPLEMENTED / REAL_RENDER_NOT_RUN / QUALITY_NOT_VERIFIED**.
User proposal: independently reusable character/scene/theme IDs, reference images once registered, dramatically reduce repeated author prompts, local-first tool that can selectively connect external LLMs/tools, transmit successful craft to other works. This is a design baseline candidate, not authorization for installing models, sending assets externally, changing existing pipeline, or publishing. Existing story v0.2 and 4-GATE remain unchanged.

## 1. Goal and boundaries
VML is a provider-independent declarative production specification / domain-specific language, not a model's native prompt syntax or another generator. It records semantic intent, approved references and asset versions; compiler produces immutable resolved shot plans, adapter-specific requests and editing instructions. Media binaries live in a local asset store and are referenced by ID + revision + checksum; secrets and model weights never go in VML/Git. A compact authoring view is a goal, not a claim of shorter provider tokens or pixel-identical output. IDs do not themselves condition image models. Real reference data or model-specific conditioning must be used; unsupported constraints block the shot instead of quietly ignoring them. Historical evidence must not be conflated with visual reenactments. Maintain aesthetic consistency without forcing different stories into the same plot or style.
Name: VML already means Vector Markup Language (W3C note, 1998), so use qualified Murim VML / M-VML and extension .mvml.xml to avoid ambiguity; public brand TBD.

## 4. SSOT and data model
Use safe standard XML for candidate authoring grammar, .mvml.xml; typed resolved JSON IR is generated only (not second editable authority). Python standard XML restricted parser/schema+semantic validation first, avoid custom parser and heavyweight GUI initially. Authoring UI serializes same source. VML refers to separate canonical manuscript/research/asset documents at pinned revisions; never copy competing full versions into two writable stores. No executable code, shell commands, arbitrary prompt-time network imports, DTD/external entities, absolute path traversal in documents. Asset paths are relative to approved root and validated for symlink/escape. Provider runtime config + secrets outside work; immutable per-shot receipt separate from declarative intent.
- Work > episode > act > beat > scene > shot > track/event. A scene contains narrative context and shots; a shot contains camera/action/time/audio references. Distinguish story time (year, location, chronology) from presentation time (frame rate rational, timeline integer frames, audio sample time). Non-linear chronology legal, explicit time jump + audience orienting cues required. Final exact duration from actual voice/edit timing, preview durations provisional.
- Typed IDs e.g. CHAR:KIM@1, STATE:KIM_JEJU_1844@1, LOC:JEJU_HOUSE@1, PROP:SEHANDO@1, STYLE:INK_WASH@1, WORLD:JOSEON@1, THEME:RELATIONSHIP@1, CAM:SLOW_PUSH@1, MOT:BOOK_OPEN@1, VOICE:NARRATOR@1, BGM:WINTER@1, SFX:PAPER@1, SRC:NMK_001@1, SKILL:SCROLL_REVEAL@1. Add work/series namespaces (global shared packs separate from episode assets), unique stable ID + immutable revision. No mutable latest reference in released manifests. Revisions are selected explicitly; change of selected revision triggers dependency invalidation, not unauthorized wholesale updates.
- Character identity pack: approved front/side/fullbody, appearance constraints, optional multi-angle and expressions, origin source/rights, identity vs costume states. State references owner character; age/era/wardrobe changes explicit. Historical likeness may be inferred/artistic and must be labeled; not a claim of appearance truth. Scene location pack: geography, layout/anchor positions, architecture, palette, time/weather variants, references. Prop: asset, shape/scale/condition/owner at story time; no generated alteration of original historical art. Style pack: palette/texture/composition/style ref/forbidden elements, independent from character.
- Narrative theme/beat: central inquiry, actor intent/conflict/action/discovery, claim IDs, audience already-knows/new disclosure, refrain/motif, transition, prohibited unsupported claims. Theme IDs guide coherence rather than force generic sentiment. Audio/narration references approved manuscript segments, voice profile, pronunciation, cue times, licensed music and effects. Subtitles use verified text, not generator glyphs.
- Registry metadata: asset URI inside approved store, SHA-256, source/date, author, license and attribution/scope (external upload, commercial use), kind, revision, approval and lineage, model/version/seed as appropriate. Evidence asset is READ_ONLY vs STAGING; generated and archival material visibly distinct. Preview of unresolved references clearly marked, no publishable export.

## 5. Illustrative syntax ONLY
```xml
<mvml version="0.1" work="SEHANDO" status="draft">
  <scene id="S014" world="WORLD:JOSEON@1"
         location="LOC:JEJU_HOUSE@1" time="1844"
         style="STYLE:INK_WASH@1"
         theme="THEME:RELATIONSHIP@1">
    <actor ref="CHAR:KIM@1" state="STATE:JEJU_1844@1"/>
    <shot id="S014_01" duration="8s" mode="living_painting"
          truth="staging" source="SRC:NMK_001@1">
      <action>책을 조용히 펼친다</action>
      <camera ref="CAM:SLOW_PUSH@1"/>
      <motion ref="MOT:BOOK_OPEN@1"/>
      <sound ref="SFX:PAPER@1"/>
    </shot>
  </scene>
</mvml>
```
These IDs demonstrate grammar; corresponding real asset files/revisions not registered, references not executable. Validation must reject unresolved IDs if compile attempted. The action is an illustrative creative reenactment, not documented physical action. Exact voice/timeline lengths await editing. Declaration-only, no provider-specific syntax in source. Reference packs define full parameters. Example immutable identity revision and multiple temporal states; explicit approved overrides. Resolve defaults through series/work/scene/shot with deterministic precedence, no cycles, prohibit overriding locked identity/rights/evidence safeguards; a shot specifies only changes. No implicit mutation carried across render order. Explicit previous-shot continuity links and start/end state snapshots.

## 6. Compiler, adapters, authoring tool
Authoring VML + registry + pinned manuscript/source references -> parser/schema -> typed ID resolver + asset hash/right/status check -> continuity/state/chronology checks -> immutable provider-neutral ShotPlan IR -> capability/budget/policy selection -> provider adapter request -> render/import -> QC -> selected approved artifact -> audio/timeline export.
- Compile deterministic plan with provenance and diagnostic IDs (UNRESOLVED_REF, TYPE_MISMATCH, REVISION_MISMATCH, CYCLIC_DEPENDENCY, UNSUPPORTED_CAPABILITY, RIGHTS_NOT_CLEARED, BUDGET_EXCEEDED). Validate before external requests or GPU use. Expanded prompt is inspection output; provider prompt, negative prompts, reference tensors/images, masks, pose, first/last frames, workflow/node bindings, model parameters kept by adapter. Never pass literal semantic character ID to unconditioned model and pretend identity control. No hardcoded scene-specific exceptions in compiler.
- Adapter capability contract: capabilities(), validate(plan), estimate(plan), submit(plan), status(job), fetch(job), cancel(job) where available; normalized result and errors. Separate Text/Research LLM, Image, Video, TTS, Music and Edit capabilities; routing by role/task, not global vendor. Manual import/export adapter for unsupported APIs (human-selected provider output, rights/manifest, explicit receipt); local mock distinctly MOCK, never real quality proof. Local queue with one GPU job at a time initially, budget/time/VRAM telemetry, selective retry. No silent cloud fallback or spend. API auth and user approval for uploads/external tools; explicit provider/model/version lock, privacy filters and separate external credentials. No new model downloads without compatibility/license gate.
- Job receipt/cache key: normalized plan + input asset hashes + provider/model/workflow/compiler rev + seed/settings + relevant upstream lineage. Cache approved assets; dirty dependency graph marks only affected shots, recompile and preview before explicit approval. Same inputs yield same plan; AI output numerical or visual exact reproducibility not guaranteed. Provider/version changes require comparative validation not automatic swap.
- Studio eventually: left project tree/asset library, central storyboard/preview, right shot inspector (ID selectors + constrained overrides, provenance), bottom multi-track timeline; queue/cost/quality panel. Human can choose reference images, lock visual identity, swap shot tool, view compiled prompt and log, manually import, reorder and compare A/B, accept/reject, track retention marker. UI is view/editor over VML, not second source. Start CLI + manifest validation/dry run + contact sheet, minimal local browser UI after pipeline proved. Use existing FFmpeg/editor utilities if available/verified; OTIO export optional. No unverified GUI/test claims.

## 7. Agent division and reusable production knowledge
Research owns source/claim records, Writer owns narrative beats/manuscript, Art Direction owns character/location/style/prop packs and aesthetic locks, Camera owns camera/shot intent, Imaging/Video owns generation candidate outputs, Audio owns voice/music/SFX/timing, Council owns independent factual/visual/story judgement, Viewer Research/Marketing owns blind feedback/packaging/analytics, Director owns gate transitions and human sign-off. All consume typed VML subsets, not full prompt bundles; agents propose scoped patches, approved versions committed after validation, no arbitrary overwrite of other role's assets. External LLMs see only required retrieved fragments, not entire library or keys. Existing roles and four gates reused; no new agent count for its own sake.
Skill registry separates knowledge from assets: template with input/output parameter types, preconditions, constraints, tested providers/settings, sample IDs, observed failure cases, evidence/score, scope, version. Example SCROLL_REVEAL: reveal readable archival scroll progressively, preserve glyphs (use authorised source/camera crop rather than generate fake), link accompanying narration cue, use validated effect; portable to maps, letters and documents, not specific plot. Research, pacing, character continuity, camera, music and subtitle rules also reusable. A skill promotion requires evidence across scenes/works, versioned review and rollback. Successful shot alone does not prove generalizable skill. Copy template/technique, not same stock plot/face or copyright-restricted source. No automatic model weight learning claim.
